# Физический Android/Chrome: частный LAN HTTPS, только синтетический прототип

Не открывает рабочую КСУ, PostgreSQL или внутреннюю систему в Интернет. Используется другой
контейнер, LAN-порт 8443, отдельный browser origin и **только** файлы прототипа. Amvera,
публичный DNS, туннели и проброс портов на роутере не нужны. Не выключайте проверку сертификатов.

## Подготовка на тестовом Windows-ПК

1. Отдельная копия этого PR: `C:\KSU\warehouse-offline-stage0`; Docker Desktop/Linux,
   уже загруженный `ksu-postgres:offline`. Установите mkcert из официального
   [FiloSottile/mkcert](https://github.com/FiloSottile/mkcert) в разрешённом для тестового ПК порядке.
   Команды ниже выполняет владелец тестового устройства. На управляемом устройстве, где
   запрещены пользовательские CA, требуется разрешённая инфраструктура сертификатов,
   а не обход политики.
2. ПК и Android подключены к отдельной тестовой Wi-Fi/LAN. Уточните IPv4 обоих устройств
   (`ipconfig` на ПК и свойства Wi-Fi телефона). Не подставляйте публичный адрес.
3. Сертификаты — вне репозитория/OneDrive. В PowerShell подставьте **реальный LAN-IP ПК**:

```powershell
$ip = '192.168.1.20' # ЗАМЕНИТЬ на IPv4 тестового ПК
$tls = Join-Path $env:LOCALAPPDATA 'KSU-Stage0-TLS'
New-Item -ItemType Directory -Force -Path $tls | Out-Null
mkcert -install
mkcert -cert-file "$tls\lan.pem" -key-file "$tls\lan-key.pem" localhost 127.0.0.1 $ip
Copy-Item (Join-Path (mkcert -CAROOT) 'rootCA.pem') "$tls\ksu-stage0-ca.crt"
```

`rootCA-key.pem` и `lan-key.pem` приватные: **не переносить на телефон, в Git или чат**.
На Android переносится только публичный `ksu-stage0-ca.crt`, например по USB. Установите его
через настройки безопасности → установка сертификата → **сертификат ЦС (CA)**; названия меню
зависят от Android. В Chrome должен открываться именно адрес, включённый в SAN сертификата.

## Ограниченный запуск

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\KSU\warehouse-offline-stage0\experiments\offline_mvp\Start-Prototype.ps1' -BindAddress $ip -Port 8443 -CertificatePath "$tls\lan.pem" -KeyPath "$tls\lan-key.pem"
```

Терминал остаётся занят. Сервер внутри контейнера обслуживает лишь whitelist прототипа;
Docker публикует порт только на указанном частном LAN-IP. Файлы приложения/БД/рабочие тома
не монтируются, фото телефона не отправляются серверу. Не используйте `--network host` и
не меняйте origin действующей КСУ.

Если Windows Firewall блокирует подключение, администратор создаёт правило только для
**IP тестового телефона**, Private-профиля и порта 8443, например в отдельном elevated PowerShell:

```powershell
New-NetFirewallRule -DisplayName 'KSU Stage0 Android HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -LocalAddress 192.168.1.20 -RemoteAddress 192.168.1.30 -Profile Private
```

Оба IP в примере заменить фактическими. Не разрешайте Public profile и любой удалённый адрес.
При AP/client isolation в Wi-Fi выберите разрешённую тестовую LAN — не меняйте корпоративную сеть.

## Проверка телефоном

1. Chrome: `https://192.168.1.20:8443/` (фактический IP). Не продолжайте через предупреждение
   о недоверенном сертификате: проверьте CA, SAN/IP, часы и срок сертификата. В DevTools при
   USB remote debugging `window.isSecureContext` должен быть true; SW установлен.
2. Только обычный профиль браузера. Дождитесь активной оболочки. Создайте отдельную локальную
   фразу, загрузите синтетический пакет/цветное фото. Выполните сценарий из README.
3. Для строгой проверки отключите **и Wi-Fi, и мобильные данные** либо включите режим полёта.
   Закройте Chrome через список приложений/force stop, откройте тот же URL (можно ярлык на
   домашнем экране). Должны открыться оболочка и разблокировка; после фразы — сохранённый пакет.
   Не очищайте storage Chrome: это уничтожит данные, а не симулирует обычное закрытие.
4. Заполните ответы, добавьте тестовое фото камерой или из галереи, подтвердите локальное
   сохранение, повторите закрытие/открытие. Сверьте ID/количество фото. Переключение в камеру
   само по себе не должно считаться подтверждённым сохранением.
5. Лаборатория: отказ квоты и памяти, затем повторный запуск. Меняйте авто-блокировку на
   1 минуту, проверьте закрытие интерфейса и восстановление. На реальном устройстве отдельно
   наблюдайте нехватку RAM/OS-kill; не заполняйте системный диск корпоративного телефона.
6. Верните Wi-Fi, остановите **только прототип** и запустите снова с теми же IP/портом/сертификатом
   и `-Build stage0-v2`; проверьте waiting update и сохранение черновика перед активацией.
7. Зафиксируйте Android/Chrome версии, RAM/свободное место, наличие Web Locks/SubtleCrypto,
   результат persist(), холодный старт, камеру/формат/размер фото, тайминг KDF и замечания.
   Продемонстрируйте, что production-origin (например 8003) и его данные не изменились.

## Завершение стенда

```powershell
docker stop ksu-offline-stage0
```

Удалите только созданное тестовое firewall-правило (администратор):

```powershell
Remove-NetFirewallRule -DisplayName 'KSU Stage0 Android HTTPS'
```

Удалите тестовый CA с телефона после пилота. `mkcert -uninstall` на ПК удаляет доверие его CA;
учтите, если тот же CA используется другими вашими тестами. Приватные ключи не распространять.
Шифрованный browser storage сохраняется до явной очистки пользователем. IP/порт/origin менять
во время проверки восстановления нельзя. Это инструкция для ручной приёмки: физический Android
в Codex Cloud недоступен; результаты такой приёмки пока не заявляются.
