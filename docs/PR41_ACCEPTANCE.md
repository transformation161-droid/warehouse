База: PR №40, `a923a5aa1e210e3f18d65cff3db60f95844e1c76`.
Независимый аудит начат с исходного HEAD №41 `9d2da1026d4f49207953e9ca8e8817709204b120`.
Рабочая Amvera/PostgreSQL не использовались. Все тесты/снимки/ведомости — синтетические.
PR остаётся Draft; Ready, merge и deploy требуют отдельного подтверждения владельца.
Черновики нарушений относятся к PR №42 и здесь не реализованы.

## Найдено и исправлено

1. На 409 исходная реализация закрывала форму, теряя введённый факт/комментарий/выбранное фото.
   Теперь поля остаются на месте. Текущая версия показывается отдельно; повтор поверх неё
   возможен только после явной сверки. Автоматического повышения expectedVersion нет.
   После сетевой ошибки форма также сохраняется; можно скачать приватную копию с исходным фото.
2. countBusy защищал часть отправок, но красная кнопка/навигация позволяли заменить форму
   во время запроса. Все действия/ввод текущей модальной формы блокируются на время отправки;
   двойное нажатие не создаёт второй PATCH/запись аудита. Фото после успешной загрузки повторно
   не загружается при обычном retry того же ввода.
3. Запоздавший poll мог перерисовать открытый редактор. Ответ poll теперь отбрасывается, если
   открылась форма/проверка, появилась очередь либо изменился пользователь.
4. Красная форма автоматически предлагала 0 для положительного учёта: теперь факт вводится
   явно, включая 0. Незаполненное поле не становится недостачей. Быстрая галочка не очищает
   фото/комментарий; уже подтверждённое соответствие не записывается повторно, расхождение
   открывается для проверки без автоматического затирания.
5. Escape у фото закрывал также исходную карточку; быстрые повторные клики могли создавать
   несколько lightbox. Исправлено. Просмотр фото/подтверждения и акта сохраняет права viewer.
6. В обзоре объект без открытых нарушений показывал «Без открытых» без общего числа.
   Теперь 0 / Всего остаётся видимым; счётчики учитывают только разрешённые пользователю записи.
7. PDF округлял дробные количества до двух знаков; XLSX не обеспечивал видимость длинного
   бренда/наименования при печати. PDF сохраняет точные количества/закупочные цены и единицы;
   XLSX переносит текст, повторяет заголовки и допускает несколько страниц по высоте.
   Расчёты Decimal/ROUND_HALF_UP, отдельные суммы недостач/излишков и null/0 сохранены.
8. Быстрый пересчёт возвращал длинный мобильный список к началу. Положение списка сохраняется
   после отметки и возврата из формы; поиск/страница сохраняются, новый фильтр начинает с начала.
   Текстовое уведомление не перехватывает быстрые касания кнопок.
9. CI №41 вообще не запускался: workflow разрешал только базу №40. Добавлена текущая база,
   проверки новых файлов, head SHA checkout, серверные/PG/browser тесты и source-only ZIP с
   повторным скачиванием/сверкой manifest (включая скрытый .dockerignore).

## Границы изменений

Новых полей/таблиц/SQL-миграции/ролей нет. Автоматический тест сравнивает все backend-файлы
(кроме генератора ведомости), SQL, модели, RLS/ACL/аудит, 22 вопроса, offline и assets с №40.
Изменения UI не обходят существующий version-checked API, CSRF и серверную авторизацию.
Одновременные операции сериализует прежняя транзакционная блокировка; проигравший получает 409.
Непроверенное actual=null остаётся непроверенным; плановые ID/учёт/цены не меняются.

Новый механизм сохранения ввода относится только к **форме пересчёта инвентаризации** в памяти.
Это не черновик нарушения и не новая постоянная очередь. До подтверждения сервером не закрывать
вкладку. При ошибке можно скачать recovery JSON с фото, хранить приватно; не присылать его в чат/Git.
Если ответ потерян после commit, прежняя версия при повторе даст 409: сверить серверный результат,
не повышать версию наугад. При закрытой инвентаризации запись запрещена независимо от UI.

## Ручная приёмка владельца (ПК и физический Android)

Выполнять на согласованной тестовой копии с синтетическими позициями. Не менять рабочую PG,
DSN/TLS/секреты/регион и не повторять инициализацию. Установленные правила PR40 остаются прежними.

1. Открыть план с четырьмя строками: учёт 1, 2, 0, 0.001; цена каждой 100. Все сначала
   «Не проверено», факт — тире, недостач/излишков нет.
2. Первую подтвердить галочкой: факт 1, «Соответствует». Быстро нажать повторно: нового
   изменения/аудита нет. Для второй красной кнопкой ввести 0, комментарий, фото: «Недостача».
3. Для учёта 0 ввести факт 1 и комментарий: «Излишек». Пустой факт и расхождение без
   комментария не сохраняются. Для 0.001 ввести 0: статус недостачи, точный учёт в ведомости.
4. Сверить итоги: план 300.10, известный факт 200.00, недостачи 200.10, излишки 100.00.
   PDF/XLSX: бренд, статус и единицы каждой строки, точные числа, читабельная печать.
5. Открыть одну строку на двух устройствах. Сохранить разный факт: вторая отправка получает
   конфликт без потери ввода/фото. Сверить серверный факт; повтор разрешить осознанно. Закрытие
   плана на другом устройстве должно запретить последующий пересчёт.
6. На Android проверить кнопки/прокрутку длинного списка, клавиатуру дробных количеств,
   выбор фото/камеру, ориентацию, отсутствие горизонтального скролла. После reload факт/фото
   остаются. Физический Android и работа камеры не подтверждаются эмуляцией Chromium.
7. Увеличить фото в карточке нарушения, подтверждении и акте; закрыть кнопкой/Escape/вне фото.
   Исходная карточка и ввод в ней остаются. Viewer может смотреть разрешённые фото без записи.
8. В обзоре/списке/паспорте сверить Открыто / Всего, включая 0 открытых при закрытых нарушениях.
   После устранения уменьшается только Открыто. Не должны появляться данные чужого объекта.
9. Завершить только полностью пересчитанный план; после завершения кнопок записи нет, API
   не разрешает новый факт. Проверить журнал изменений и неизменность плана.

Перед будущим внедрением — свежий backup рабочей PG и независимая проверка восстановления,
проверка отсутствия неподтверждённых отправок, отдельное разрешение владельца. Эта задача
не запускает обновление Amvera и не переводит PR в Ready.
