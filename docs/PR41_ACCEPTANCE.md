# PR41 — Ускоренный пересчёт, ведомости и нарушения

Основа: установленный в Amvera PR40 (GitHub SHA `a923a5aa1e210e3f18d65cff3db60f95844e1c76`).
**Публикация PR41 отдельно, только после CI и ручной проверки. Изменений схемы PostgreSQL нет.**
Черновики нарушений не входят в этот PR (планируются в PR42).

## Сценарии

1. **Быстрый пересчёт.** На доступном плане руководитель и КСУ видят две кнопки в каждой строке.
   - Зелёная галочка для ещё не проверенной позиции устанавливает `actual=expected` и сохраняет результат по существующему API с `expectedVersion`.
   - Если позиция уже отмечена с расхождением, галочка **не затирает** прежние данные: открывается полная форма редактирования.
   - Красный перечёркнутый круг открывает форму фактического количества, комментария и фото. При отсутствии позиции начальное поле `actual=0`. Комментарий при расхождении обязателен.
   - Кнопки не создают новое поле статуса: статус вычисляется из `actual` и `expected`, поэтому `null` остаётся «Не проверено».
2. **Мобильная адаптация.** На узких экранах таблица превращается в карточки: наименование, бренд, номер, статус, учёт/факт и две кнопки с крупными зонами нажатия. На ПК — таблица.
3. **Ведомости.** PDF и XLSX содержат бренд и статус каждой позиции; сумма и факт по незаполненным позициям не подменяются нулём.
4. **Нарушения.** Фотографии в карточке и акте проверки увеличиваются по нажатию и закрываются по кнопке, Escape или касанию вне изображения.
5. **Счётчики.** На обзорной странице (руководитель и КСУ), карточках объектов и в паспорте объекта отображается «Открыто / всего». Открытые: все, кроме «Устранено»; всего: все записи независимо от статуса.

## Приёмка (тестовые данные, без влияния на реальные инвентаризации)

- [ ] CI: Python tests и проверка синтаксиса JS успешно пройдены.
- [ ] XLSX содержит колонки «Бренд» и «Статус», суммы в правильных столбцах; PDF корректно печатается.
- [ ] На ПК / Android оба действия видны, карточки без горизонтальной прокрутки.
- [ ] Галочка сохраняет факт для непроверенной позиции; красная кнопка требует комментария при расхождении.
- [ ] При повторном нажатии и конфликте версии 409 данные не перезаписываются.
- [ ] Просмотрщик не получает кнопки записи и не может менять факт.
- [ ] Увеличение фото работает в карточке нарушения и акте проверки.
- [ ] Открытые / всего корректно пересчитываются после закрытия нарушения и при разных объектах.
- [ ] На Android и ПК после перезагрузки страницы статус и фотографии сохранены.

**Не требуется:** новая миграция, повторное восстановление PostgreSQL или перенастройка Amvera.
