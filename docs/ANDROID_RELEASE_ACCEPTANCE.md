# Физическая Android-приёмка новой релизной оболочки — только синтетика

Это подготовка отдельного локального стенда. Испытаний на физическом Android в Codex нет;
прежняя приёмка PR30 не заменяет эту проверку брендинга, viewer и режимов. Amvera/main/8003 не нужны.

1. На Windows с прежним Docker Desktop проверить выбранный SHA этой ветки. Собрать без каких-либо данных:

   ```powershell
   $sha=git rev-parse HEAD
   docker build -f Dockerfile.offline-release --build-arg "KSU_BUILD_SHA=$sha" -t ksu-offline:rc .
   docker build -f Dockerfile.offline-acceptance --build-arg RELEASE_IMAGE=ksu-offline:rc -t ksu-offline-acceptance:rc .
   ```

2. Использовать доверенный локальный HTTPS: сертификат с SAN `127.0.0.1`, `localhost` и частным IPv4 Windows,
   например192.168.1.20. Установить публичный локальный CA на Windows и отдельный тестовый Android по прежней
   инструкции mkcert. Приватный CA-ключ не переносить. В Chrome не должно быть предупреждений о сертификате.
   Для обращения backup-контейнера к этому стенду разрешён тот же LAN IP; добавить его в SAN сертификата.
3. В отдельной доверенной частной сети (не публичном Wi-Fi) запустить:

   ```powershell
   .\tools\Start-Release-Acceptance.ps1 -HostAddress '192.168.1.20' -CertificatePath 'D:\KSU-private\tls\cert.pem' -KeyPath 'D:\KSU-private\tls\key.pem'
   ```

   Разрешить порт8017 только в частном профиле firewall, если требуется, решением владельца. Скрипт firewall
   не меняет. Без HostAddress стенд публикуется лишь на127.0.0.1; телефон такой адрес Windows не увидит.
   Не использовать0.0.0.0, публичные адреса, туннели или8003.
4. Скрипт создаёт новый named volume, deployment ID, контейнер, случайные пароли и четыре **ДЕМО**-аккаунта:
   demo-manager, demo-inspector, demo-viewer(s1), demo-unassigned(без объектов). Нет Source-параметра/корпоративной
   БД. Непустой volume seed повторно не инициализирует. Private accounts.json/state.json находятся в напечатанном
   `%LOCALAPPDATA%\KSU-Control\synthetic-acceptance\<UUID>`; не отправлять их в GitHub/чат.
   Runtime использует production image, seed helper остаётся в другом image/завершённом контейнере.
5. В Chrome Android открыть `https://192.168.1.20:8017/`. Проверить точное название
   «ИНСТРАКТ | Складской учет», официальный знак на входе/в шапке, favicon. Отдельно проверить PWA-название/иконку
   на домашнем экране. Результат SVG-иконки физически ещё не подтверждён; при ошибке выпуск блокировать.

Для следующих команд `<папка>` — путь профиля, напечатанный launcher. Меняется только его контейнер:

```powershell
& '<папка>\Set-Release-Acceptance.ps1' -Directory '<папка>' -Mode off
& '<папка>\Set-Release-Acceptance.ps1' -Directory '<папка>' -Mode pilot
& '<папка>\Set-Release-Acceptance.ps1' -Directory '<папка>' -Mode pilot -ViewerAccess off
& '<папка>\Set-Release-Acceptance.ps1' -Directory '<папка>' -Mode pilot -ViewerAccess enabled
& '<папка>\Set-Release-Acceptance.ps1' -Directory '<папка>' -Mode stop
```

Смена режима сохраняет БД, origin, deployment ID и локальную очередь. Данные/volume/backup не удаляются.
Не переносить корпоративную копию в этот стенд и не использовать его как production launcher.

## Протокол владельца

| Шаг | Ожидаемый результат |
|---|---|
| Inspector в pilot открывает `/offline-visit/`, входит и загружает назначенный s1 | Доступен один назначенный выезд и22 вопроса, нет s2 |
| Без сети заполняет ответы, два нарушения, фото камерой и галереей | «Сохранено на устройстве», затем «Ожидает отправки» |
| Закрывает/открывает Chrome без сети, вводит ту же локальную фразу | Все ответы, фото и устойчивые ID сохранены |
| Пока очередь не отправлена, Windows переключает off, телефон возвращает сеть | Отправка запрещена, локальная очередь сохранена, новые акт/нарушения/фото не приняты |
| Возвращает pilot, отправляет тот же выезд | «Принято сервером», один акт, два добавленных нарушения и два фото, выезд завершён |
| Повтор отправки/закрытие и открытие браузера | Прежний receipt, новых записей/фото нет |
| Manager в отдельном браузере | Видит прежние и новые записи/историю/фотографии, отчёты работают |
| Viewer в отдельном профиле или инкогнито (для просмотра, не для offline) | Бейдж «Только просмотр», толькоs1, без личных полей и кнопок изменения; общий интерфейс, детализация, разрешённые фото и отчёты работают |
| Unassigned viewer | Пустой список объектов, никакого автоматического доступа |
| Viewer при pilot и off пробует запись/offline/импорт/backup, в том числе прямые API |403 и ноль изменений бизнес-таблиц |
| Logout и другой аккаунт, возврат из истории браузера | Нет данных/очереди другого аккаунта; подтвердить текущую сессию |

Не очищать профиль инспектора и не передавать его локальную фразу viewer. В MVP один выезд на профиль;
этой приёмке достаточно одного завершённого выезда, много-выездный архив не заявляется.
Потеря ответа после commit, ожидаемая версия, поздний конфликт и смена cookie после preflight дополнительно
проверяются автоматизацией на SQLite и PG; не изображать их физическое выполнение, если владелец их не воспроизвёл.

Записать Android/Chrome/Windows/Docker версии, SHA из health, название/иконку, pilot/off/viewer pass/fail,
количество новых актов/нарушений/фото и повтор без дублей. В GitHub передать только обезличенный итог
с синтетическими метками, без accounts.json, DB, фото, CA-ключей и секретов. При блокере сохранить очередь,
перевести только синтетический стенд в stop, не менять Amvera.
