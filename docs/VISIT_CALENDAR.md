# Issue #17 — календарь выездов

Исходная ветка: `integration/visits-inventory`, коммит `bca38a5` (Draft PR #16).
Календарь — представление существующей коллекции `visits`. Новых таблиц, миграций,
серверных статусов и параллельного хранилища выездов нет.

## Работа с календарём

1. «План выездов» → «Календарь». Список оставлен и открывается по умолчанию при первом входе.
2. Выберите «Месяц», «Неделя» или «День». Доступны предыдущий/следующий период,
   «Сегодня» и выбор даты. Неделя начинается в понедельник; месяц включает соседние дни.
3. Нажмите дату: ниже появятся **все** выезды дня по фильтрам. На компьютере в ячейке
   видны первые три карточки; на смартфоне — количество и знак `!` при просрочке,
   полные статусы и действия находятся в карточках выбранного дня.
4. «Запланировать выезд»: дата уже подставлена, обязательно выберите объект.
   Обе кнопки создания в календарном режиме используют выбранную дату.
   Исполнитель-инспектор фиксируется сервером; руководитель выбирает исполнителя.
5. «Подробнее» открывает карточку со статусом, целью, исполнителем и переходом к объекту,
   акту проверки и истории. «Изменить / перенести» открывает прежнюю форму выезда.
   Для отмены обязательна причина. Для выполнения — прежний полный чек-лист.
6. Фильтры объекта, статуса (в том числе «Просрочен») и исполнителя (только руководитель)
   общие для календаря и списка. «Сбросить фильтры» возвращает весь доступный план.
   Сводные показатели над фильтрами относятся ко всему доступному плану.

Вид, период, дата и фильтры сохраняются в sessionStorage отдельно для аккаунта в текущей
вкладке. После перезагрузки приложение открывает обычную стартовую страницу; при возврате
в «План выездов» настройки восстанавливаются. Если браузер запрещает sessionStorage,
календарь работает, но настройки живут только до перезагрузки. Сами выезды там не хранятся.

Кнопки дат доступны с клавиатуры; стрелки перемещают выбранную дату на день/неделю,
Enter/Space открывают день. В календарных диалогах Tab остаётся внутри диалога,
Escape закрывает его. На смартфоне сводные показатели сокращены, чтобы календарь был ближе.

## Даты, права и данные

Дата выезда остаётся строкой `YYYY-MM-DD`. Расчёты календаря используют локальный полдень
и календарные операции, без преобразования даты в UTC. «Сегодня» определяется в часовом
поясе устройства. Календарный день выезда одинаков для пользователей разных часовых поясов;
UTC сохраняется для времён аудита. Просрочка — только вычисляемый признак `planned` с датой
до локального сегодня, без фоновых записей в БД.

Inspector видит назначенные объекты и может менять только назначенные себе запланированные
выезды. Manager видит общий доступный план и может переназначать по прежним правилам.
Завершённые/отменённые записи защищены обеим ролям. Кнопки UI повторяют эти ограничения;
серверные ACL, SQL-триггеры, optimistic version, идемпотентность и аудит не изменены.
Устаревшая версия получает 409; доступ к чужой записи не появляется через фильтры.

Все проверки используют синтетические данные и временные БД. Amvera, PostgreSQL,
произвольные дела дня из #2, большие импорты #10 и внешние интеграции не изменены.
Перетаскивание, push и геолокация в этот этап не входят.

а также прежнюю локальную контейнерную приёмку. Workflow доставки на Amvera не меняется.
Логи и синтетические снимки — в артефакте `integration-acceptance` на странице CI.

## Ограничения

Календарь использует текущий snapshot доступных выездов с опросом раз в 3 секунды,
без новой серверной пагинации. Для очень большого плана потребуется отдельная оценка
производительности. Предыдущие ограничения SQLite/резервирования из PR #16 сохраняются.
