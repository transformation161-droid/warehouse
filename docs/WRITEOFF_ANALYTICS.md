# Списания и аналитика — предварительная управленческая витрина

Issue #15. Основа: `feat/issue-21-decision-versions`, `4311f5e93cfdadc6b7c4d97d61defe4c7a5ee2e9` (Draft PR #23).

**Не официальная отчётность.** Бизнес-ключ документов и исторические пересечения ещё проверяет владелец процесса. Программа не объединяет похожие исторические книги автоматически. Предупреждение присутствует на панели и в каждой выгрузке.

## Использование

Войти руководителем или инспектором, открыть **«Списания и аналитика»**. Прежний раздел **«Списания и решения»** сохранён; кнопка «Реестр и импорт» открывает его. Календарь, выезды, импорт и резервное копирование продолжают использовать существующие механизмы.

Общие фильтры периода по дате акта (обе границы включительно), объекта, инструмента, причины, типа решения, МОЛ, расследования и категории случая одновременно меняют карточки, шесть графиков и таблицу. Пустая категория выбирается отдельным флагом «Не указано»; одноимённый непустой текст остаётся самостоятельным значением. В подсказках до 100 значений; другое точное значение можно ввести вручную. Источник не переименовывается и не нормализуется неявно.

Нажатие на полосу графика сужает общий срез. Нажатие на финансовую карточку показывает строки, участвующие в её сумме; отдельная ссылка показывает строки с неизвестным значением. Документы и решения переходят к строкам текущего среза. В каждой строке доступны исходные поля, лист и номер Excel, действующая версия документа и история исправлений; исторический состав открывается в существующем реестре. Текущая версия документа и версия введения конкретной строки показаны отдельно: частичное исправление сохраняет неизменённые строки.

Период, объект и показатель графиков всегда видны на компьютере и смартфоне. Дополнительные фильтры раскрываются отдельно; применённые условия можно снимать по одному. На смартфоне результаты показаны карточками со всеми пятью количественными/финансовыми значениями и кнопками источника/истории. Настольная таблица имеет собственную горизонтальную прокрутку. Сетевое ожидание ограничено 30 секундами; ошибка оставляет возможность повторить загрузку с теми же фильтрами.

«Операционные отчёты» — прежний раздел «Аналитика и отчёты»: проверки, нарушения, первичные расхождения инвентаризаций и недельная сводка. «Списания и аналитика» — готовые результаты списаний и решений из XLSX. Функции прежнего конструктора и его CSV/XLSX/PDF сохранены.

## Определения и точность

| Показатель | Правило |
| --- | --- |
| Документы | Число различных логических документов, имеющих действующие строки в срезе. Связи исправлений из PR #23, а не SHA, название или номер Excel. Документ может встречаться в нескольких месяцах/категориях: групповые количества документов **не складываются** в общий итог. |
| Действующие решения | Число действующих строк результатов, прошедших все фильтры; не автоматически число юридических актов. |
| Количество по источнику | Точная сумма заполненного количества. Единицы неоднородны и источником не нормированы. Дробная часть визуально отделена, все цифры сохранены. Есть счётчик и детализация дробных строк для проверки источника; это не автоматическое признание ошибки. |
| Стоимость списаний | Сумма заполненной стоимости источника. Не автоматически установленный ущерб. |
| Остаточная стоимость | Отдельная сумма заполненной остаточной стоимости. Не прибавляется к стоимости. |
| К возмещению | Отдельная сумма заполненного назначения к возмещению. |
| Фактически возмещено | Отдельная сумма заполненных фактически возмещённых сумм. |

Утверждённое правило PR46: эти два поля учитываются самостоятельно. Любое соотношение допустимо; разница не вычисляется, не показывается и не используется для предупреждений или автоматической категории обязательств.

Каждая карточка содержит определение и число заполненных/неизвестных/некорректных строк. При отсутствии известных значений сумма — `null` / «Не указано», включая пустой срез; подтверждённый `0` остаётся нулём. Отрицательные, бесконечные и некорректные сохранённые значения не превращаются в нули. Допустимы до 4 десятичных знаков денег и 6 количества, как в импорте. Арифметика — `Decimal` с точностью 50 знаков. Числа API передаются десятичными строками; браузер только форматирует их, финансовых вычислений через `Number`/float нет. Проценты ширины полос рассчитаны сервером и служат только отображению.

Без корректной даты строка не получает вымышленную дату импорта. В общем срезе она входит в отдельную группу «Без даты»; при заданном периоде исключается. Есть отдельный фильтр отсутствующей/некорректной даты и счётчик качества. Проверки пропущенных дат моделируют сохранённые исторические записи; требования действующего XLSX-импортера не ослаблены.

CSV и XLSX экспортируют выбранный срез полностью, независимо от страницы. Сводки содержат все группы; строки содержат исходные поля и ссылки идентичности/версий. В XLSX денежные и количественные десятичные значения — **точный текст**, а не округлённые числа Excel. Пустая ячейка означает неизвестное значение. Есть лист определений; текстовые формулы CSV/XLSX обезврежены. Для дальнейшей арифметики в Excel нужно явно выбрать требуемую точность преобразования.

## Исполнение и защита

`GET /api/writeoff-analytics` и `GET /api/writeoff-analytics/export/{summary|rows}.{csv|xlsx}`. Новый модуль — `server/writeoff_analytics.py`; новых таблиц и миграций схемы нет.

Один потоковый SQL-запрос под текущим серверным пользователем читает исключительно действующие записи через связи документов/версий и исключает `decision_retirements`. Агрегирование выполняется на сервере с Decimal. PostgreSQL использует курсор по 64 строки; в браузер идут максимум 100 строк (интерфейс — 25), до 12 групп каждого категориального графика и последние 24 месячные группы, включая отдельную группу без даты. Усечение отмечено; сводная выгрузка содержит все группы. Поля исходных ячеек/формул не поднимаются для обычной панели.

Оптимизация #25 материализует только метаданные внутри того же SQL-снимка, без постоянного кэша. В PostgreSQL исключение архивных ID использует эквивалентный `NOT IN` по гарантированно непустому первичному ключу, с сохранением RLS. Для курсора локально задано `cursor_tuple_fraction=1`: агрегирование действительно читает его до конца. Схема, индексы, RLS, глобальные настройки PostgreSQL и квоты ресурсов не меняются. Подробности и сопоставимые замеры: [предрелизная приёмка](PRERELEASE_ACCEPTANCE.md).

Показатели, графики и страница строк формируются из одного SQL-снимка. Исправление, подтверждённое во время чтения, не смешивает версии в ответе. При экспорте интерфейс передаёт отпечаток среза: изменение состава/версии приводит к HTTP 409 с предложением обновить панель, а не к несовпадающей выгрузке. Браузерный кэш привязан к сессии, роли, доступным объектам и ревизии.

Сохранены PostgreSQL RLS и ограничения непривилегированной runtime-роли. Инспектор видит только назначенные объекты; параметры URL не расширяют доступ. Ни чтение, ни экспорт не создают факты и не меняют аудит. Источник и журнал доступны через прежние авторизованные API. Ответы `no-store`, публичный сервер отдаёт только явно разрешённый новый JS-ресурс.

Выгрузка формируется целиком на закрытом диске до успешного HTTP-ответа; временные XML XLSX находятся там же, а не в 32 МиБ `/tmp`. По одной аналитической выгрузке на процесс, предел файла 128 МиБ и времени 120 секунд; используются существующие проверки свободного места. Файлы удаляются после ответа и обработанных ошибок.

```bash
python -m unittest tests.test_writeoff_analytics -v
python writeoff_analytics_flow_test.py
python -m tests.pg_environment --image ksu-postgres:test --output var/postgres-checks
python -m experiments.analytics.run --image ksu-postgres:test --output var/analytics-acceptance
```

Последние две команды поднимают только локальные временные Docker/PostgreSQL с TLS. Синтетический нагрузочный стенд: приложение с клиентом — 0,5 CPU / 1 ГиБ; отдельные source/restore PostgreSQL — по 0,5 CPU / 1 ГиБ. Работа не обращается к Amvera.
