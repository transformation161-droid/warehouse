## Разрешённые конфликты

В SQLite сохранены атомарная замена правил выездов и новые таблица/триггеры импорта.
CI выполняет оба новых браузерных сценария. Дополнительно исправлена ошибка автоматического
слияния `/api/history`: обе части UNION теперь возвращают JSON `data`, необходимый для
проверки назначенного исполнителя. Права не обходятся ради доступа к истории.

Проверка обновления теперь допускает новую пустую таблицу `decision_records`, при этом
сравнивает отпечатки всех прежних таблиц и повторяет открытие БД. Никакого reseed.

## Проверки

Все данные синтетические; реальные БД, корпоративные книги и Amvera не использовались.

- 60 unittest: успешно, без пропусков; включая реальный локальный TLS, права HTTP/SQL,
  атомарность, конфликты версий, аудит, идемпотентность и backup/restore.
- Отдельная репетиция обновления БД, созданной настоящим кодом исходного коммита:
  сохранены 52 записи, 52 события аудита, 2 фото, импорт и 2 аккаунта;
  повторное обновление, вход, фото, XLSX/PDF, новые действия и запреты проверены.
- Браузерные сценарии: `smoke_test.py`, `v11_flow_test.py`, `visits_flow_test.py`,
  `decisions_flow_test.py` (включает выезд до импорта и отмену/историю после него).
- Синтаксис `app.js`, `sync.js`, `decisions.js`, компиляция Python, `git diff --check`.

Новый `tests/test_integration.py` проверяет выезды и импорт в одной БД, версии,
отмену, раздельный аудит, повторное открытие, дедупликацию, отзыв доступа к объекту

## Ограничения и риски перед выпуском

Это интеграция для review, без обновления работающей системы. PostgreSQL не начат.
PR #12/#13 остаются открытыми. Настройки Amvera, тарифы и ресурсы не менялись.
Workflow доставки ограничен main и не запускается этой веткой.

Сохраняются ограничения SQLite: одна реплика/worker, предел БД 256 МиБ и запас диска
для больших XLSX. Лимит ingress и WAL на фактическом хранилище требуют отдельной приёмки.
HTTP backup ограничен 16 МиБ: для больших реестров независимая копия и восстановление
должны быть обеспечены отдельным этапом до внедрения. Локальный snapshot проверен,
но это не подтверждает доступность внешней копии работающего пилота.
Нагрузочные метрики PR #13 не выдаются за повторный нагрузочный прогон этой интеграции.
