# Действия владельца для запуска

Кандидат основан на принятом PR №35 (`b7b0c62`, стенд 8020). Полную UI/PWA-приёмку не
повторять. Merge/deploy пока не разрешены. Подробные команды: [план внедрения](PRODUCTION_RELEASE.md).

1. **До окна:** подтвердить подходящую для SQLite WAL файловую систему `/data`, одну реплику,
   UID/GID 10001, фактические квоту/место/цену, путь активной БД и возможность возврата старого образа.
   При NFS/неподтверждённых блокировках остановить выпуск до решения о хранении.
2. **Согласовать выпуск:** выбрать способ интеграции [стека PR](PR_INTEGRATION.md), утверждённый
   SHA и ручную доставку в существующую Amvera. Отключить внешнюю автодоставку и прежние
   GitHub backup/delivery workflow до любого будущего merge. Сейчас main не менялся.
3. **Скачать успешный CI source bundle**, сверить SHA/manifest, собрать тот же образ локально
   для инструментов владельца. В пакет не добавлять БД, пароли, сертификаты или backup.
4. **В окне остановки:** завершить очереди/receipts пользователей, закрыть запись, остановить
   всех писателей. Скачать полный frozen `/data` в приватное хранилище. Выполнить
   `New-Offline-Backup.ps1` с точным `-DatabaseRelativePath`, затем `Prepare-OwnerRelease.ps1`
   в **новый** output. Сверить оба отчёта, SHA, сохранность всех таблиц и независимый restore.
   Эти файлы/результаты не отправлять в GitHub/Codex. При ошибке обновление не начинать.
5. **После отдельного go/no-go:** загрузить v4-копию на новый `/data/live-v4/ksu.sqlite3`,
   старую БД сохранить. Настроить точный origin, постоянный production deployment ID,
   offline/viewer сначала off, export-work, `KSU_LOCAL_BACKUP_MODE=daily`. Вручную обновить
   существующий сервис проверенным source bundle. Не запускать старый runtime параллельно.
6. **До допуска записи:** health показывает утверждённый SHA и успешный локальный restore;
   владелец проверяет существующие аккаунты, выбранные старые акт/фото/отчёт/history/receipts
   и контрольные данные миграции. Включить viewer с персональными ACL, проверить свои/чужие
   данные и запрет записи. Получить свежую проверенную внешнюю копию. Это smoke переноса данных.
7. **Открыть работу:** online сначала, offline pilot — по согласованному списку inspector IDs.
   Ежедневно проверять `localBackup.healthy`, место и наличие внешней копии; после рестарта
   убедиться в догоне расписания. На Windows обновить **обе** старые задачи новой регистрацией
   с process-only Bypass: сохранить/отключить прежние точные имена, PlanOnly → новая пара →
   успешные backup+health. Глобальную Execution Policy не менять, GPO не обходить.
8. **При сбое:** закрыть записи и применить [таблицу отката](PRODUCTION_RELEASE.md#откат-без-потери-новых-записей).
   До новых записей возможна старая версия со старым нетронутым набором. После новых commits —
   сохранить текущую v4/receipts, выключить функции флагами, backup/restore и совместимое исправление;
   старую БД поверх новых данных не возвращать. Измерить фактический RTO у владельца.

## Что согласовать до внедрения

- Подтверждение FS/WAL/блокировок и прав тома; если несовместимо — отдельное решение о хранении.
- Способ интеграции полной вершины, утверждённый SHA, ручная доставка, окно остановки и ответственный
  с правом go/no-go; возможность возврата прежнего бинарника/настроек. Merge/deploy — отдельное разрешение.
- Допустимые RPO/RTO, место/защита внешних backup и ответственный за ежедневный контроль.
  Постоянно включённого внешнего узла нет/неизвестен: при потере тома/аккаунта Amvera возраст
  последней Windows-копии может превышать сутки. Либо принять этот риск, либо подтвердить
  уже имеющийся корпоративный узел. Новый платный ресурс не предлагается к созданию.
- Наличие штатного backup Amvera **в текущем тарифе**, реальные квота/расходы, правила хранения
  двух локальных копий и ручной архив/очистка Windows exports/старых сборок. Авторасширение не разрешено.
- Персональные viewer/site ACL, production deployment ID, список offline pilot и порядок обработки
  неподтверждённых очередей; полномочия manager для backup. Корпоративные реквизиты согласовывать приватно.
