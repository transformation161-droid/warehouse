# PR46: независимая проверка и границы выпуска

Работа выполнена в существующей `feat/writeoff-analytics-v1-20261113` поверх `release/pr41-accepted-baseline` (`cc0b182`). Последнее уточнение владельца имеет приоритет над ранним описанием issue42: импортируется только построчный отчёт по списаниям; «Аналитика инвентаризаций» — исключительно образец результата. Импорт агрегатов, засев Q1 и выдуманные пересечения не реализуются. Любой новый квартал требует своего построчного отчёта.

## Исправления после ревью заготовки

- Импорт: обязательный отчётный квартал, реальный выбор листа/заголовков/диапазона, сопоставление 17 полей, явное подтверждение алиасов существующих объектов; показ итогов, нулевых строк, исключённых из диапазона документа строк, ошибок с листом/ячейкой и полного CSV ошибок. Неизвестные объекты не создаются.
- Устранено отклонение корректных денег из-за числовых хвостов Excel: только numeric-ячейки, неотрицательные значения, погрешность до 0,00000001 ₽ к допустимой точности 4 знака. Исходная запись ячейки сохранена; количество исправленных представлений явно показано. Значимая лишняя точность и ошибки текстовых чисел отклоняются. Формулы требуют отдельного разрешения сохранённых результатов.
- Исправленный файл проходит существующий append-only механизм версий: выбранный акт → сравнение → подтверждение; неоднозначные ID требуют ручных соответствий. Отдельные строки с одинаковыми бизнес-полями сохраняются. Повтор файла не создаёт дублей. Конфликт версии отменяет запись целиком.
- Интерфейс использует компоненты, навигацию и стиль PR41. Новая вкладка в отчётах; прежние отчёты сохранены. В прежний паспорт объекта добавлены те же фильтры/показатели/разрезы/реестр. Из меню скрывается только пересчёт инвентаризаций, его данные и API сохранены. Viewer сохраняет прежний интерфейс; аналитика для него закрыта.
- Полные фильтры, поиск и страницы реестра; все объекты в квартальной матрице, выбор показателя, рост/снижение, Top-N/все, переходы из групп; CSV/XLSX выбранного среза. Δ считается к предыдущему календарному кварталу, при отсутствии сравнимых данных остаётся неизвестной. Пустые кварталы обозначены «Нет загруженных данных».
- Кэш изолирован по учётной записи/сессии/ревизии, старый ответ не попадает в новую сессию. Асинхронная аналитика не перерисовывает открытый диалог. Запись защищена от двойного нажатия и дополнительно проверяется на сервере.
- Уточнение/исключение даты инвентаризации выполняет только manager с основанием, CSRF, версией и идемпотентным ID операции. Используется существующая частичная версия документа и аудит; исходные поля и строки не меняются. По умолчанию — уникальные `siteId + дата акта`; несколько событий в один день могут давать заниженную оценку.
- Production gate открывает проверенные методы/пути адресно; inspector только читает назначенные объекты; viewer не получает аналитику, выгрузки и импорт. RLS и SQL authorizer не отключаются.

## Проверки

Целевые автоматические проверки: точные суммы и пустые поля; 0 количества; даты актов вне отчётного квартала; несколько квартальных отчётов; повтор файла; исправление и одновременные изменения; алиасы; отмена/rollback; права и CSRF; источники/версии; XLSX/CSV и snapshot. Отдельно проверены PostgreSQL 17 с `ksu_runtime` без owner/BYPASSRLS, RLS при прямом SQL и конкурентные уточнения; настоящий встроенный UI в Chromium, ширина 412 px, upload → preview → commit → dashboard → XLSX, исправление акта, смена пользователей без утечки кэша. Полная UI/PWA-приёмка PR41 не повторяется.

Приватная сверка предоставленного рабочего XLSX прошла на временных SQLite и PostgreSQL 17: **39 строк, 5 нулевых, 56 единиц, 356787.50 стоимости, 113827.87 остаточной, 113827.87 к возмещению, 116992.36 фактически возмещено**. В источнике 11 импортируемых формул; чтение кеша разрешено явно. Пустые денежные поля не заполнены нулями. +3164.49 ₽ — предупреждение о несогласованности, не установленная переплата. На PostgreSQL проверена также выгрузка. Все имена/МОЛ/строки и экспорт оставались только в одноразовом приватном стенде; после проверки он удалён. Исходные файлы не входят в коммит, Docker-контекст, CI или комплект предпросмотра. Второй файл в приложение не импортировался.

Актуальные результаты CI и артефакты — во вкладке Checks данного PR. Комплект `PR46-Preview` публикуется только после успешных Linux API/PG/browser, реального Docker/HTTPS и Windows PowerShell проверок. [Короткий запуск и приёмка](PR46_PREVIEW.md).

## Что осталось до выпуска

1. Владелец принимает встроенный UI на вымышленных данных из проверенного комплекта. Production push, merge и перевод из Draft отдельно не разрешены.
2. Затем согласуется включение `KSU_WRITEOFF_ANALYTICS_ENABLED=on`. По умолчанию `off`. `KSU_OFFLINE_MODE=off`, существующий viewer-флаг, DSN, разделение ролей и Dockerfile не изменяются.
3. Применимых новых миграций PostgreSQL нет: используются существующие v4 таблицы `decision_*`, JSON метаданные и аудит. Авто-DDL production при запуске не добавлен. Временная SQLite — только локальный scratch импортера, не рабочая БД.
4. Для загрузки нужен существующий локальный scratch с минимум 768 МиБ свободного места; исходный XLSX ≤30 МиБ, очередь импорта одна. Это прежние лимиты проекта; ограниченный диск Amvera необходимо учитывать перед фактическим включением.
5. Владелец подтверждает алиасы и отчётный период своей рабочей книги, актуальность кеша формул, основания уточнений дат и неидентифицированные исходные ID. Данные Q1 появятся только после отдельного исходного отчёта Q1. Веб-аналитика остаётся предварительной до бухгалтерской сверки источников.

Amvera, действующие БД, main и платные ресурсы не изменялись. Предпросмотр работает с новой локальной PostgreSQL, а не с реквизитами рабочего приложения.
