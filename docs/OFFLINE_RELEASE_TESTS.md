Большой тест использует75 синтетических BLOB по2МиБ, не корпоративные фотографии: это проверка
хранения/копирования/побайтовой сохранности, не нагрузки декодирования JPEG и не доказательство locking тома Amvera.
Время локального SSD не является обещанием RTO на Amvera. Предварительный неконтейнерный прогон150МиБ
тоже прошёл, но приведённые выше показатели относятся именно к ограниченному Docker-прогону.
Локальный образ был development-probe с меткой исходного PR30; это не готовый для развёртывания артефакт.
CI строит новый образ с SHA проверяемого merge snapshot, а будущая доставка должна фиксировать
SHA/образ согласованного кандидата. Изменения production config отсутствуют.
Дополнительная отрицательная проверка: legacy-копия с неизвестной колонкой пользователя не получает
успешный migration-report; финальная v3-схема проверяется целиком до выдачи отчёта, исходник неизменен.

Шесть офлайн-сценариев на каждом backend: холодный offline-рестарт с ответами/двумя фото и устойчивыми ID;
истёкшая сессия/чужой аккаунт; потеря ответов фото и акта **после реального commit**; восстановление receipt
после рестарта браузера **и переключения сервера в off**, ноль дублей; отзыв доступа/ранний конфликт без
загрузки фото; смена cookie после preflight; отказ IndexedDB/последующее сохранение; поздний expectedVersion
конфликт после фото с откатом всего акта и устойчивым409. Несколько проверок входят в один полный сценарий.
Дополнительный седьмой сценарий — прежний online UI обоих аккаунтов без demo и новых финансовых разделов.

Команды воспроизведения (разработческая среда с requirements-dev, Chromium и Docker, только синтетика):

```bash
CADDY_BIN=/path/to/verified/caddy python -m unittest discover -s tests -v
python -m tests.release_upgrade
python -m tests.offline_stage1_environment --release --output /tmp/private-release-pg
python -m tests.offline_stage2 --release --backend sqlite
python -m tests.offline_stage2 --release --backend postgres
docker build -f Dockerfile.offline-release --build-arg KSU_BUILD_SHA="$(git rev-parse HEAD)" -t ksu-offline:rc .
python -m tests.release_container --image ksu-offline:rc
```

Ограниченный150МиБ Docker-прогон и Windows parser зафиксированы в `.github/workflows/offline-release.yml`.
Workflow запускается только на PR в ветку №30, ничего не публикует в registry, не содержит deployment,
не выгружает private-файлы в artifacts. Результат Actions/окончательный SHA см. в Draft PR.

Не выполнены и блокируют выпуск: owner-local проверка фактической схемы/полной реальной копии,
staging/restore с подтверждением владельца; физический Android именно с новой release-политикой;
WAL/locking/UID/одна реплика и способ immutable build delivery на Amvera; свободное место, бюджет,
независимый backup по расписанию/RPO/RTO; решение о допустимости одного выезда на профиль и безопасной
смене профиля; согласование окна, cohort, отката и запуска. Подробные действия — `OFFLINE_RELEASE.md`.
