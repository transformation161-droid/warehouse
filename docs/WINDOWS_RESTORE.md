# Локальная приёмка резервной копии на Windows

Владелец сообщил о независимой копии: integrity_check=ok, foreign_key_check без ошибок, 36 записей, 2 изображения с миниатюрами. Этот файл не поступал в Codex/GitHub. Следующий шаг — восстановить его и проверить приложение на компьютере владельца.

Переносной комплект **KSU-Restore-Windows-x64.zip** предназначен для Windows 10/11 x64. Включает Python runtime, Tcl/Tk, существующие FastAPI/SQLite и интерфейс, Pillow, XLSX/PDF и DejaVu Sans с лицензией. Установка Python, терминал, интернет и права администратора для использования не нужны. Комплект не подписан; обходить корпоративные политики или отключать защиту не требуется.

Для владельца: распаковать ZIP полностью, дважды открыть **KSU-Restore.exe**, выбрать скачанную базу, выбрать локальную тестовую папку вне синхронизации, затем следовать пяти шагам окна. Полная инструкция поставляется рядом с EXE: [ИНСТРУКЦИЯ.txt](../deploy/windows/ИНСТРУКЦИЯ.txt).

Инструмент читает оригинал как обычный файл, сверяет SHA-256, работает с отдельными новыми файлами в уникальной папке. SQLite не открывает оригинал. Рядом с работающей БД WAL/SHM/journal — отказ. Восстановление не использует hard links, поэтому не зависит от поддержки NTFS. Аккаунты и их прежние пароли сохранены; активные сессии и счётчики входа очищены только в тестовой базе. Нет bootstrap, инициализации или сброса паролей.

Проверяются integrity/FK, все фото/миниатюры, сохранность таблиц при восстановлении, оба входа/роли, доступное каждому фото через API, JSON/XLSX/PDF и запрет экспорта базы для inspector. Ручная часть — открыть запись и фото, сверить отчёт с ожидаемым результатом под обоими аккаунтами. Edge/Chrome открываются с двумя отдельными локальными профилями; иначе предлагается обычное и приватное окно браузера. Программа слушает только IPv4 loopback 127.0.0.1 со случайным свободным портом, не меняет firewall и не обращается к Amvera. Пароли используются только в локальных запросах, поля очищаются после отправки; в итог пароли/содержание записей не входят.

При завершении сервер останавливается и повторно сверяется оригинал. Итог **ИТОГ-ПРОВЕРКИ.txt** различает полную и незавершённую проверку, содержит количества и контрольную сумму. Тестовая папка и профили остаются у владельца, не загружаются автоматически. Не размещать комплект или данные в OneDrive/Dropbox/сетевых папках. Не отправлять базы/фото/профили в GitHub, Codex или третьим лицам. Инструмент не подтверждает сохранность Amvera после перезапуска — это отдельный этап #4.

## Сборка и проверка для разработчика

Отдельная ветка `feat/issue-4-windows-restore`, без изменения ветки размещения и без слияния с main. Новый workflow `Build portable Windows recovery tool` выполняется только для этой ветки (или вручную). Существующие Amvera release/backup workflows и переменные не изменяются. Windows standard GitHub runner для публичного репозитория; платные дополнительные сервисы не подключаются.

Workflow устанавливает зависимости, запускает `tests.test_windows_restore`, собирает PyInstaller 6.16.0 onedir x64, затем запускает именно собранный EXE с синтетической базой 36/2 и проверяет открытие Tk-окна. Только после успеха публикуется ZIP + SHA256.txt + BUILD.txt в artifact на 14 дней. Test DB, пароли и тестовые результаты с данными в artifact не включаются; упаковка использует явный список исходников и проверяет отсутствие файлов баз/ключей.

Изменение `server/reports.py` только добавляет необязательный KSU_PDF_FONT для шрифта в Windows-комплекте. Путь по умолчанию Linux сохранён. Работающий контейнер Amvera не пересобирается и не обновляется. `portable/` не включается в контейнерный build context текущим allowlist.

Локальные проверки разработчика:

```sh
.venv/bin/python -m unittest tests.test_windows_restore -v
.venv/bin/python -m unittest discover -s tests -v
```

Для самостоятельной технической сборки на Windows с Python (владельцу это не нужно):

```powershell
python -m pip install -r requirements.txt pyinstaller==6.16.0
python -m PyInstaller --noconfirm --clean deploy/windows/ksu-restore.spec
```

Для повторной проверки скачивается свежий комплект; artifact по умолчанию истекает через 14 дней. Архив не является установщиком или обновлением Amvera. Фактический результат запуска на компьютере владельца остаётся открытым до его подтверждения.
