# Будущий раздел «Настройки → Пользователи» — требования, не реализация

В пилоте только два персональных аккаунта из однократного owner init. Нет нового UI/HTTP API
управления пользователями. Таблица users допускает любое число сотрудников с неизменными IDs;
ограничение «два» относится только к начальному config. Для добавления сотрудников в будущем
не потребуется пересоздавать БД, повторять init или переносить/терять акты/историю/фото/receipts.

Будущий объём:

- Только manager: создание персонального сотрудника, назначение manager/inspector/viewer и
  объектов, деактивация, безопасный сброс пароля. Inspector/viewer — серверный отказ независимо
  от UI; нельзя доверять переданной клиентом роли или дать runtime произвольный UPDATE users.
- Атомарная проверка прав и аудит каждого административного действия: кто/когда/над кем,
  изменение роли/активности/назначений до/после и результат. Пароль, hash пароля и reset token
  не включаются в audit/ответы общего state/логи. Служебные admin/backup роли сотрудникам не выдавать.
- Неизменный user ID, проверка уникальности персонального логина; нельзя удалить последнего
  активного manager, повысить себе роль через клиент, удалить историю или перепривязать авторство.
- Сброс выдаёт новый случайный секрет/короткоживущий одноразовый token закрытым каналом,
  отзывает активные сессии, не показывает прежний пароль. Желательно обязательное изменение
  временного секрета при первом входе. Учитывать CSRF, rate limit, идемпотентность и конфликты.
- Деактивация и снятие назначения немедленно закрывают новые API/photo/export доступы;
  ранее законно полученную офлайн-копию нельзя стереть у отключённого устройства. Нужны явные
  правила для неподтверждённых очередей, устройств и смены роли, без автоматической потери данных.
- Добавление пользователей/назначений на существующей БД, аудит, отзыв сессий, backup/restore
  проверяются отдельно. Первичный initializer не становится командой reset/force/upsert.

Реализация будет отдельной задачей/PR после согласования. В этот релиз она не добавляется.
