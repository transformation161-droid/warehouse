## Прекращение начислений и контроль диска

[Официальные правила](https://docs.amvera.ru/general/price.html): состояния «запущен», «запускается» и «работает с ошибкой» тарифицируются. В состояниях **«остановлен» или «заморожен» списаний нет, если все файлы проекта находятся в пределах дискового лимита**. Завершение Python-процесса вместо остановки ресурса не подходит.

В 7 ГБ учитываются **Code, Artifacts, Data и repo вместе**, а не только `/data`. За превышение действует 35 ₽/ГБ/720 часов; оно запрещено сметой. Поэтому до запуска/после сборок проверять общий объём в Amvera, дополнительно сохраняя лимиты приложения 256 MiB SQLite и 2 GiB `/data`. При необходимости очищать только доказанно воспроизводимые старые артефакты, не БД/фото.

На окончание согласованных 720 часов: получить и проверить независимую копию, остановить/заморозить именно согласованный проект, проверить статус/объём и отсутствие дальнейших начислений. Не удалять данные вслепую. После 30 дней остановки Amvera может автоматически заморозить проект с удалением артефактов; при превышении диска после заморозки возможна потеря проекта. Независимая копия обязательна. Удаление проекта необратимо и требует отдельного подтверждения.

[Автоплатёж](https://docs.amvera.ru/general/topup.html) необязателен и по документации выключен по умолчанию; при привязке он повторно пополняет баланс при остатке менее 100 ₽. Для пилота не включать его. Если уже включён — проверить и отключить в «Баланс» перед оплатой/запуском. Состояние автоплатежа аккаунта пока не подтверждено и не изменялось. Никакие операции с картой не выполнялись.

## Доставка из GitHub с минимальным доступом

[Amvera поддерживает](https://docs.amvera.ru/applications/git/webhooks.html) два документированных варианта:

1. Автоматическая настройка — fine-grained GitHub token с Contents: Read-only и Webhooks: Read and write. Только `transformation161-droid/warehouse`, короткий срок, без доступа к остальным репозиториям/аккаунту.
2. Ручная настройка для публичного репозитория — URL репозитория, целевая ветка, проектный секрет webhook и событие `Workflow runs`/push. Агент создаёт webhook через GitHub API. Не передавать основной пароль Amvera или бессрочный classic PAT в GitHub.

Предпочтение для публичного warehouse: ручной проектный webhook после успешного CI, без передачи GitHub PAT в Amvera. Текущая GitHub-интеграция читает PR/CI, но запрос списка webhook возвращает `Resource not accessible by integration` (403). Поэтому для создания webhook нужен отдельный fine-grained token только для warehouse с Webhooks: Read and write; Metadata: Read-only добавляется GitHub. Секрет `KSU_GITHUB_WEBHOOK_TOKEN` подготовлен в защищённых настройках, назначение — только `api.github.com`, не чат/код. Если будет выбрана автоматическая настройка Amvera, дополнительно понадобится Contents: Read-only; не расширять права без необходимости.

[Официальный MCP Amvera](https://docs.amvera.ru/MCP/doc-mcp-ru.html) поддерживает Bearer token из кабинета. Документация не подтверждает проектное ограничение или read-only роль этого токена: нельзя называть его узким проектным доступом. Для проверки использовалась временная сессия; основной пароль не сохраняется в приложении/CI и для доставки GitHub→Amvera не требуется. Новые постоянные токены Amvera или пользователи не создавались.

## Хранение и готовность

[SQLite на Amvera](https://docs.amvera.ru/databases/sqlite.html) размещается в постоянном `/data`. Фото, аудит и записи — в `/data/ksu.sqlite3`; одна реплика/один worker. [Папка сохраняется при перезапуске/пересборке](https://docs.amvera.ru/general/FAQ/data-saving.html), платформа описывает три экземпляра данных на разных узлах. Это не заменяет отдельную консистентную копию SQLite.

На «Начальный Плюс» [включены копии `/data` за последние два дня](https://docs.amvera.ru/applications/backups.html). Дополнительно подготовлен независимый зашифрованный snapshot; включение внешнего расписания — только в проверенных бесплатных квотах. Реальное восстановление на Amvera ещё не выполнялось, поскольку платный проект не создан.

Конфигурация `amvera.yml` сверена с официальной [Docker-документацией](https://docs.amvera.ru/applications/configuration/docker.html): Dockerfile, порт 8000, persistenceMount `/data` поддерживаются. Контейнерный тест ранее прошёл реальные лимиты 0,5 CPU/1 GiB, пик около 250 MiB, restart/rebuild/restore. Для проверенного SHA `035f2e2` PR #6 оба job `server-tests` и `amvera-container` завершились SUCCESS. Публичного приложения пока нет.
