# Общий рабочий шаблон чек-листа

В этом релизе один шаблон `global`. Manager открывает «Настройки» → «Общий шаблон чек-листа»:
добавляет пункт, меняет формулировку и раздел, переставляет вопросы внутри раздела/разделы целиком,
архивирует и возвращает пункты. Архив показывается отдельно. Физического удаления нет;
минимум один и максимум 200 действующих вопросов. Inspector и viewer не имеют редактора;
прямые записи проверяет сервер, роли не задаются клиентом.

Запись идёт через прежний `/api/changes`: сессия/Origin/CSRF, SQL guards/RLS, expectedVersion,
идемпотентный mutationId, атомарная очередь отправки. Изменение порядка — один batch, конфликт
не применяет часть перестановки. Аудит содержит автора/UTC/before/after, изменения раздела,
формулировки, position и archived. При конфликте сохраняется приватная очередь; не удалять её
и не отправлять содержимое в чат. Восстановление/повтор не создаёт дубль.

Справочник вопросов хранится в прежних JSON records; новые поля position/archived/templateId
не требуют DDL на старте. `current_checklist()` централизованно выбирает только действующие
вопросы, учитывает порядок и сохраняет новую immutable content-hash версию. Прежние
checklist_versions не меняются и не удаляются. В завершённом акте — version hash и снимок
section/title в каждом результате; акт неизменяем. Связанный finding сохраняет questionId,
а архивная запись вопроса остаётся доступной для исторической связи.

Ранее выданный офлайн-пакет использует **свой** checklistVersion. Изменение/архивирование
текущего вопроса не заменяет данные пакета, срок жизни/ACL/expectedVersion проверки сохраняются.
При получении старого пакета сервер проверяет его закреплённую версию; после commit/restore
повтор возвращает прежний receipt. Обычный онлайн-черновик теперь также закрепляет версию
и вопросы при начале проверки, сохраняет их в локальном draft и теле pending request.
Поллинг не обновляет формулировки посреди проверки. Черновик можно скачать приватно.

Черновик старого клиента без version/questions не переименовывается автоматически и не
удаляется. Его нельзя молча отправить по новому шаблону: скачать копию, сверить вопросы и
явно начать новый черновик. Работающих пользователей/рабочих очередей до этого пилота не было.
Нельзя очищать IndexedDB, менять deployment ID или повторно инициализировать БД для обновления
шаблона. Редактор не меняет остальные разделы приложения или отдельную офлайн-PWA.

Для чистой БД owner init создаёт утверждённые вопросы/разделы и первую версию без проверок,
фото или демо-записей. Шаблон 22 вопросов не утверждается автоматически. После запуска
manager меняет его штатным редактором без повторной первоначальной настройки.

Расширение позже: resolver `current_checklist(con, template_id='global')` изолирует выбор
шаблона; в первом релизе другие IDs отвергаются. Будущий реестр шаблонов/назначений объектам
свяжет template ID с immutable version hashes. Старые IDs вопросов/версий/актов/receipts и
содержимое выданных пакетов сохраняются. Нужны явные правила выбора шаблона при подготовке
пакета и миграция назначения, а не пересоздание БД или переписывание старых снимков. Реестр
нескольких шаблонов и UI выбора объекта-шаблона в текущий объём не включены.
