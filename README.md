# ИНСТРАКТ · КСУ Контроль — версия 1.1 (локальный прототип)

Рабочий автономный прототип системы контроля складского учёта: выезды на объекты, чек-листы, реестр нарушений, инвентаризации и аналитика.

## Быстрый запуск

**Самый простой способ:** скачайте файл `ИНСТРАКТ_КСУ_Контроль.html` из ответа ChatGPT и откройте его в Chrome/Яндекс Браузере. Он содержит все стили и скрипты и не требует установки программ.

Для работы с исходным проектом:

1. Распакуйте ZIP-архив.
2. Откройте `index.html` в браузере. Если браузер ограничивает сохранение на `file://`, запустите локальный сервер: `python -m http.server 8000` в каталоге проекта и откройте `http://localhost:8000`.
3. В правом верхнем углу переключайте интерфейс «Андрей / Эльман» — это **демонстрация**, не отдельные учётные записи.
4. В «Проверки и выезды» откройте «Новый выезд». Заполните вопросы; каждый ответ «Нарушение» требует описания и создаёт отдельную карточку.
5. В «Нарушения» назначьте ответственного, срок, статус и комментарий к устранению.
6. В «Инвентаризации» создайте пересчёт вручную либо скачайте шаблон CSV, заполните его в Excel и загрузите через «Импорт CSV».
7. В «Аналитика и отчёты» меняйте период, объект, группировку. Экспортируйте CSV для Excel или печатайте в PDF.
8. В «План выездов» назначайте объект, дату, цель и исполнителя; после заполнения чек-листа выезд отметится выполненным.
9. Кнопка «Недельная сводка» в обзоре, плане или отчётах открывает отдельный управленческий отчёт с печатью PDF; также доступен CSV за текущую календарную неделю.
10. В «Настройки» выгружайте резервную копию JSON, восстанавливайте её и очищайте демоданные.

## Что действительно реализовано

- Справочник 12 объектов с паспортами и изменяемыми ответственными.
- Электронная проверка: 22 пункта из рабочих материалов, статусы «соответствует / нарушение / Н/П», серьёзность, срок, описание, ответственное лицо и фото (сжатие до сохранения).
- Журнал завершённых проверок и распечатка акта.
- Автоматическая регистрация нарушений, ручное добавление, статусы, просрочка, повторные нарушения за 90 дней.
- Реестр инвентаризаций с позициями ТМЦ, ценами, учётным и фактическим количеством; недостачи/излишки считаются отдельно.
- Импорт CSV с проверкой обязательных колонок, формата даты, названия объекта, неотрицательных значений и дробных чисел; группы создаются по объекту + дате + названию.
- Конструктор сводной аналитики по проверкам, нарушениям и инвентаризациям с группировкой по объекту, месяцу, категории, ответственному, фильтрами периодов и печатью.
- Выгрузка отчётов CSV (Excel-совместимый формат UTF-8 с BOM), печать PDF из браузера и JSON-резервное копирование.
- План выездов, связи с проведёнными проверками, контроль просроченных выездов и загрузки исполнителя.
- Управленческий отчёт за текущую неделю: проведённые проверки, замечания, устранённые, просроченные, инвентаризации, приоритетные объекты. Форматы печать/PDF и CSV.
- Адаптивная мобильная версия и отдельные стартовые экраны Андрея и Эльмана.

## Ограничения первой версии (важно)

- **Это локальная автономная демоверсия.** Данные сохраняются в `localStorage` каждого браузера, а не в общей базе. Андрей пока НЕ увидит изменения Эльмана со своего устройства.
- Переключение ролей **не является авторизацией или защитой данных**. Не загружайте в эту версию конфиденциальные корпоративные сведения.
- Данные демонстрационных проверок и инвентаризаций **вымышлены**, они не отражают реальные результаты компании.
- Импортируются файлы **CSV**, а не `.xlsx` напрямую. Отчёты выводятся в CSV, который открывается в Excel. Нативные XLSX и шаблоны Word/PDF следующего этапа требуют отдельного кода.
- Фото хранятся в локальной базе браузера; это ограничено по объёму. Перед очисткой браузера сделайте экспорт JSON.
- Интеграции с FaceKit, Битрикс24, БИТ.Строительство и 1С **не подключены**.
- Расчёт недостачи из первичного пересчёта **не является подтверждённым ущербом**. Нужна дополнительная стадия расследования и утверждения.
- План выездов в локальном прототипе общий лишь для одного браузера. Не является задачей Битрикс и не синхронизируется с ним.
- История изменений текущей локальной версии ограничена; серверная схема предусматривает журнал аудита.

## Переход к корпоративной версии

В каталоге `supabase/schema.sql` есть проект схемы PostgreSQL / Supabase с таблицами объектов, проверок, ответов, нарушений, инвентаризаций, строк пересчёта, фото и журнала изменений. Также предусмотрены роли manager / inspector и основные политики Row Level Security.

**SQL — проект миграции, не развёрнут и не подключён к интерфейсу.** Потребуются проверка архитектуры и безопасности, настройка Auth, закрытого хранилища фото, преобразование приложения на работу через API, журнал версий чек-листа и тесты. Рекомендуем вести эту разработку в Codex / Git-репозитории. До корпоративного согласования использовать только обезличенные тестовые данные.

## Структура архива

- `index.html` — оболочка веб-приложения;
- `styles.css` — оформление и адаптивная вёрстка;
- `app.js` — бизнес-логика, данные, отчёты, обработчики событий;
- `supabase/schema.sql` — предложенная серверная схема следующего этапа;
- `CODEX_HANDOFF.md` — описание дальнейших задач разработки;
- `tests/smoke_test.py` — автоматизированная проверка основных сценариев;
- `dashboard_preview.png`, `mobile_preview.png` — снимки экранов.

## Переход с v1.0 без потери записей

1. В старой версии: «Настройки» → «Скачать резервную копию JSON».
2. Откройте v1.1 и в «Настройки» → «Восстановить из JSON» выберите скачанную резервную копию.
3. Новое поле `visits` добавляется автоматически; прежние проверки, нарушения и инвентаризации сохраняются.
4. После проверки своих записей продолжайте работу. До серверного внедрения не работайте с конфиденциальными данными компании.

Публиковать только после согласования ИНСТРАКТ и проверки прав / журналирования / резервного копирования. Это является условием реальной совместной работы Андрея и Эльмана.
